# Native QWERTY local presentation slice

The presentation worker owns a new `src/os/native-keyboard-keys.ts`, focused
tests and a private resource-render check. It consumes the corrected English
local initialization evidence in `native-keyboard-invocation-contract.md` and
the immutable `lower-first-paint/qwerty-first-paint.json` continuation. Do not
consume the withdrawn provisional language-family result.

Implement the ordinary existing-profile Settings name request's local QWERTY
component: decoded source layout/materials, 45 source character labels, English
dictionary label, runtime pane visibility/alpha, and the precisely scoped
retained animation submissions. Preserve the source hierarchy and shared asset
immutability. Source messages and styles must remain resource-derived; preserve
unresolved message-style boundaries rather than inventing typography.

Keep an explicit separation between initialization/property writes and later
controller submissions. The runtime worker owns global prepare/update counts,
root ordering, mode-selector/footer reconciliation and the captured lower
transition image. This slice must not choose an overall first-frame time or
sample every character key with the disabled-key clip. Record exact source
target scope and order for each retained property write; no filename inference.

Prefer a pure helper returning a posed layout or explicit immutable presentation
state, using existing source binding/sampling helpers. Coordinate any required
renderer API change with the orchestrator before editing shared modules.
The worker must not edit `native-layout.ts`, `native-renderer.ts`, stock app
reducers, the scene, or public delivery in this slice.

Acceptance for this component: original corrected local pane/controller output
comparison, source immutability, real source font/textures rendered at 320×240,
and changed-input/cache checks where relevant. Preserve native material/text
styles. A renderer check is not a native LCD pixel oracle; global composition,
input and final browser/native comparison remain required. Parameterize scratch
and report paths under the SSD firmware artifact root and commit a reproducible
runner if one is needed. Commit coherent code and evidence, then report the
commit, checks and unresolved differences for sequential integration.
