## Writer

The vol object vtable is `0x31ed3c`. Slot 17 is `0x17aeec`. That function
loads the cache byte at `0x3771d1+3` and branches to the Pattern setter
`0x2072f4`:

| Cache byte | Pattern frame | Texture |
| ---: | ---: | --- |
| 0–3 | 4 | `HudSnd_B_04` |
| 4–17 | 3 | `HudSnd_B_03` |
| 18–37 | 2 | `HudSnd_B_02` |
| 38–57 | 1 | `HudSnd_B_01` |
| 58–255 | 0 | `HudSnd_B_00` |

The only store to that byte is `0x2c5018`. It sends `hid:USER` command
**0x00170000** (`HID:GetSoundVolume`) and, when the SVC result is
non-negative, writes command-buffer byte `+8` into the cache. A negative
result skips the store. Callers are the boot fill `0x2bb86c` and the refresh
at `0x2d91f8` (cache byte `+5` in {1, 3, 5}). Neither caller writes an
immediate.

The session is `hid:USER`, not a config-save block:

- `0x2b8810` tail-calls the opener `0x2bd874` with the name pointer at
  `0x303d5c`, which is the string `hid:USER` (`0x327446`).
- The handle slot is `0x373af8`. The same slot's command `0x000A0000` at
  `0x2c4fc0` is `HID:GetIPCHandles`.
- [HID:GetSoundVolume](https://www.3dbrew.org/wiki/HID:GetSoundVolume) returns
  one `u8`. libctru documents that byte as the volume slider, range 0–63.
  This title's buckets accept any byte; slider values 58–63 are the only
  in-range values that select frame 0.

The image byte at `0x3771d4` is `0x00`. That is the pre-call cache. It is not
a committed slider reading: a successful `GetSoundVolume` overwrites it, and
nothing in `code.bin` stores a constant there. Treating image 0 as frame 4
would hide the missing slider. The frozen stills do not identify one of the
five textures by themselves, and this slice does not pick a frame from them.
